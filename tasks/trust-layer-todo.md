### T2.3 · XLSX white-font heuristic ✅ DONE — scope materially widened after empirical verification
- [x] **The original plan ("scan `xl/sharedStrings.xml` only") turned out to be wrong, not just narrow — verified live before implementing, not assumed.** Generated real `.xlsx` files with `openpyxl` and `xlsxwriter` (both already installed) and inspected the actual XML. Finding: **openpyxl never produces `xl/sharedStrings.xml` at all** — its default output stores every cell as an inline string (`t="inlineStr"`, `<c><is>...</is></c>`) directly in `xl/worksheets/sheetN.xml`, even for heavily repeated values. A sharedStrings-only scan would have silently done nothing on every openpyxl-generated file, regardless of content. Fixed by checking **both** storage mechanisms: `trust.py`'s `_scan_xlsx_hidden_text()` scans `xl/sharedStrings.xml` (`<si>` entries) when present, **and** every `xl/worksheets/sheetN.xml` for `<is>` inline-string cells (`_xlsx_sheet_parts()` — numeric sort, same pattern as `_pptx_slide_parts()`). One warning per offending part (sharedStrings.xml and/or each sheet), mirroring the PPTX per-part-aggregation design.
- [x] Verified the SpreadsheetML run schema live too: `<r><rPr><color rgb="FFFFFFFF"/></rPr><t>text</t></r>` — a **third** distinct schema variant found across this feature (unlike DOCX's `w:val`/PPTX's unprefixed `val` with 6-hex color, SpreadsheetML's `color` uses an unprefixed `rgb` attribute in **8-hex ARGB** format). `_xlsx_run_is_white()` checks the last 6 hex chars equal `FFFFFF` and accepts a bare 6-hex value too, in case some producer omits the alpha channel.
- [x] **A second, more significant finding, documented prominently rather than left implicit:** cross-checked with both libraries' whole-cell coloring APIs (`openpyxl`'s `Font(color=...)`, `xlsxwriter`'s `add_format({'font_color': ...})`) and confirmed neither embeds color in the string content at all for that (by far the most common) case — both route it through the cell's `s="N"` style index into `styles.xml`. ### T2.4 · Bidi control characters (gated on RTL fixture) ✅ DONE — scope narrowed after the gate caught a real false positive
- [x] **The RTL fixture gate did its job — it failed on the range the plan originally specified, so the range shipped is narrower than planned.** Verified empirically (not assumed) with real Hebrew/Arabic prose and a real W3C-recommended mixed-direction construction before committing to a range:

The embedding/override range is separately well-motivated: Unicode deprecates it in favor of isolates, so modern tooling is unlikely to emit it innocently, and it's the exact mechanism behind a real disclosed attack.
